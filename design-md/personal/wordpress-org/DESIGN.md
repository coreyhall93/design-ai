# WordPress.org Design System

WordPress.org is the open source home of WordPress — the software, plugins, themes, and community. Design here embodies "from many, one tool." It is community-driven, accessible, reliable, and focused on empowering users and developers worldwide. Visual style is straightforward, trustworthy, with the iconic blue and a no-nonsense yet warm personality.

**Design Philosophy:** Code is poetry. Designs should be simple, functional, inclusive, and reflective of the diverse WordPress community. Prioritize open source values: transparency, extensibility, and user freedom.

---

## 1. Visual Theme & Atmosphere

Practical, clean, and community-oriented. Blue (#0073aa classic or updated #3858e9) as the signature color. White and light grays for backgrounds. Emphasis on documentation, download flows, and showcasing community contributions. Feels established and dependable without being stuffy.

Density: Functional — good information hierarchy for docs, directories, and support.

---

## 2. Color Palette & Roles

Classic WordPress blue combined with modern neutral system.

### Key Colors

| Color Name | Hex Code | Usage |
|------------|----------|-------|
| WordPress Blue (classic) | `#0073aa` | Primary brand, links, CTAs on .org properties |
| Updated / System Blue | `#3858e9` | Modern interactive (aligning with WPDS) |
| Success Green | `#008a20` | Active plugins, success |
| Neutrals | Standard grays | Backgrounds, text |

Many .org properties (make.wordpress.org, developer.wordpress.org, etc.) use variations. The core blue remains iconic.

Semantic roles follow similar patterns to other WP properties, increasingly using shared tokens where applicable.

---

## 3. Typography Rules

System sans-serif for modern pages. Clear hierarchy for headings in docs and news. Monospace for code examples (core to developer resources).

Scale supports long documentation: larger display for hero sections, readable body text.

---

## 4. Component Stylings

- Download buttons prominent with blue.
- Plugin/theme cards with ratings, screenshots, author info.
- Navigation: Global header with "Get WordPress", search, community links.
- Documentation: Clean sidebars, code blocks, notes/callouts.
- Forms: Standard for support, contact, etc.

Community sites use consistent patterns for forums, make sites, etc.

---

## 5. Layout Principles

Information-dense but scannable. Hero sections for key actions (Download, Showcase). Grid layouts for directories (plugins, themes, WordCamps).

Generous spacing in docs for readability. Responsive with priority on desktop for developer resources.

---

## 6. Depth & Elevation

Subtle for cards and modals. Focus on content over heavy visual effects. Clean borders and backgrounds.

---

## 7. Do's and Don'ts

**Do:**
- Celebrate the community and openness.
- Use the classic blue prominently for brand recognition.
- Make documentation and resources scannable and accessible.
- Align where possible with broader WP ecosystem (Gutenberg, etc.).

**Don't:**
- Overcomplicate with heavy design trends.
- Forget mobile users and global audiences.
- Introduce inconsistent blues or styles across properties.

---

## 8. Responsive Behavior

Core download and showcase pages adapt well. Mobile menus for navigation. Docs remain usable on smaller screens with collapsible elements where helpful.

---

## 9. Agent Prompt Guide

Capture the open source, community spirit of WordPress.org.

- Signature blue (#0073aa or #3858e9 for modern contexts) for primary elements.
- Clean, readable typography with strong code support.
- Functional layouts that put information and downloads front and center.
- Components: Straightforward buttons, cards for plugins/themes with meta, clear navigation.
- Overall: Trustworthy, no-frills yet welcoming. "Code is poetry" — designs should feel like reliable tools built by and for the community.

Prompt example:
"Design this for WordPress.org using its classic open-source aesthetic. Use the iconic WordPress blue (#0073aa or modern #3858e9) for accents and CTAs. Clean system fonts, excellent docs-style hierarchy, functional components. Make it feel community-powered, accessible, and true to the 'democratize publishing' mission."

Reference the global brand alignment work for consistency with other WP properties (e.g., Automattic bar in footers where applicable).
